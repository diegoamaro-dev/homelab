  which a blocking lock would have prevented.
* The script ran to completion under `set -euo pipefail`: the full `forget` output was
  written, and its `trap 'rm -rf "$SNAP_DIR"' EXIT` fired — `/tmp/homelab-backup-snapshots`
  is absent, so the shell exited through the trap rather than dying mid-run.
* No stderr, warning or error appears anywhere in the run.
* The lock listing was **also** empty at the attended run (`/tmp/i5_locks.txt`, 0 bytes), so
  both I-5 runs are now covered.

**One non-argument, recorded deliberately:** the 03:30 `backup-probe` success proves nothing
here — it runs `restic snapshots --no-lock` and would have succeeded with a lock present. It
was excluded from the reasoning when the item was open and remains excluded now.

## 5. Correction to a prediction the roadmap carried

**The roadmap's I-5 sequencing note was wrong, and the error is now proven on real data.**

`ROADMAP.md`, `CURRENT_STATE.md` and `AMAROLAB_HANDOFF.md` all stated that editing `PATHS`
would **restart the S-10 would-remove trail from zero**. It does not.

`restic forget` evaluates each `host,paths` group independently, so a `PATHS` change starts a
new group whose own trail begins at zero while **the report as a whole is unaffected**.
Observed across the boundary:

| Run | Would-remove count | Set |
|---|---|---|
| 2026-08-17 03:00 (13-path) | 10 | — |
| 2026-08-18 03:00 (13-path, last of the old group) | 11 | `{106316a6 39c4f6fe 5818569e 599d98f8 89966886 98bcc984 9b50911b 9f37d45d d03f0e19 f41248e1 f889868d}` |
| 2026-08-18 12:40 (attended, first 16-path) | 11 | identical |
| **2026-08-19 03:00 (unattended, 16-path)** | **11** | **identical** |

The set did not reset, and the new group contributed nothing to it.

**Consequence for S-10, which is the item that cares:** every one of those 11 snapshots sits
in a group that is now **frozen at 22 members** and that **no future snapshot can ever join**.
The trail S-10 must plan against is a closed set, not a growing one. This strengthens rather
than weakens the S-10 input recorded on 2026-08-17.

The triad has been corrected accordingly. The 2026-08-17 record is a dated historical
document and is left as written.
